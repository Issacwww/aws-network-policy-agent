## eBPF test-run decision

- **Fact:** Local `BPF_PROG_TEST_RUN` is not feasible: the effective capability set is empty, `/proc/sys/kernel/unprivileged_bpf_disabled=2`, the syscall probe returns `EPERM`, `bpftool` is absent, and the repository has no existing green prog-test harness. See `ebpf-feasibility.log`.
- **Fact:** No eBPF source was changed, so `build-bpf` is not a required change gate. Tier/ipcache merge semantics are covered by `dns_tier_test.go`; deployed eBPF behavior is frozen in the two R9 cluster regressions and the R14 redirect-order cluster assertion.
